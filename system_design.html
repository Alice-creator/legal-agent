Checklist deploy

Server (1 lần):

  1. Provision Ubuntu 16GB + cài Docker + Docker Compose.
  2. docker-compose: db (pgvector/pgvector:pg16) + backend (FastAPI/uvicorn, reuse manager/backend) + caddy (reverse proxy + auto-TLS).
  3. Đưa INDEX lên: pg_dump bảng documents + chunks (đã embed) từ Mac → scp → restore vào Postgres server. (Server không-GPU nên KHÔNG embed lại — chỉ nhận vector dựng sẵn.)
  4. Domain → Caddy (HTTPS tự động). Mở chỉ :443.
  5. Bật log query (ghi bảng query_log) cho vòng cải tiến v2.

App v1 (mỗi lần phát hành):

  1. Export model AITeamVN → ONNX · publish lên HuggingFace (có version).
  2. Build Tauri cho 3 OS (.exe / .dmg / .AppImage); config trỏ HF model + endpoint server.
  3. App lần đầu chạy: tải model từ HF (~1-2GB) → cache. Update model = tải bản mới theo version.

⚠️ Hạng mục kỹ thuật cần giải khi build

Embed query trong Tauri (CPU): export AITeamVN → ONNX, chạy bằng ort (onnxruntime Rust) + tokenizers (Rust). 1 query trên CPU ~1-3s, OK. Đây là phần khó nhất của v1.
Trích xuất query-PDF: PDF text → PyMuPDF (nhẹ, nhúng được). PDF scan → cần OCR (nặng) → đẩy server hoặc bảo user dán text. Khác với kho (Surya offline).
Auth / license server trả phí: nhiều user + server tính phí → cần token/API-key gắn app để chặn truy cập trái phép. Quyết định cơ chế license.
Chuyển index Mac→Server: pg_dump/restore (lần đầu + mỗi khi re-embed). Cân nhắc dump chỉ chunks+documents, hoặc logical replication nếu cập nhật thường.
Riêng tư: query rời máy lên server (cho BM25+log). Court data → cân nhắc ẩn danh log + TLS bắt buộc.

Nối tiếp Phiên 2: E2 (embed) đang chạy → E3 (endpoint hybrid trong manager/backend) → E4 (eval synthetic) → đóng gói server + Tauri theo blueprint này.
