v1 · USER (live)
Client mỏng: tải MODEL · embed query · gửi {vector+text} · hiện kết quả. Chạy laptop yếu. Server trả về sau khi hybrid-only (không rerank).
v2 · DEVELOPER (máy Mac)
Off 99%, bật khi cần. Build kho + vòng cải tiến: log query → rerank batch → đào hard-negative → fine-tune embedder → re-embed → đẩy server.
☁️ Server · 16GB · no-GPU
Giữ Index 33k + documents. Chỉ hybrid retrieve (CPU dư sức, nhiều user) + log query. KHÔNG rerank/fine-tune (không GPU) → đẩy hết sang Mac.

Model publish→app tải; fine-tune ⇒ re-embed index. ⚠️ query log = dữ liệu toà → ẩn danh / giữ cẩn thận.

🟩 reuse Phiên 1 · 🟦 index (ở SERVER) · 🟨 kết quả · ⬚ ranh giới máy · 🔁 vòng offline (Mac). Live = hybrid-only mãi mãi; rerank CHỈ trong vòng cải tiến offline để fine-tune model.

Chunk kiểu gì?
→ sliding-window ~400-512 tok (15% overlap) + parent-child
late-chunking bất khả (fine-tune cap 2048 < doc p90 ~8.9k)
cosine hay dot?
→ L2-norm + cosine
trên vector chuẩn hoá, dot ≡ cosine; giữ HNSW chuẩn
vector hay halfvec?
→ halfvec(1024)
float16 nửa RAM/disk, gần như không mất recall — quan trọng ở server 16GB no-GPU
Hybrid hay dense-only?
→ hybrid ngay (RRF k=60)
đã có sẵn tsv; luật cần khớp token chính xác (Điều X, số vụ)

→ defer, có điều kiện

E0 · Bật stack

E1 · Tách section + chunk (offline M5)
regex bao-dung-dấu nhận 4 header → chunk facts/reasoning nếu có, không thì cả doc · tag bản-án/quyết-định · chỉ bucket clean/minor (tránh rác OCR).
E2 · Embed + index (offline M5/MPS)
AITeamVN (L2-norm) · build HNSW halfvec_cosine_ops (m=16, ef_construction=64).
E3 · Endpoint hybrid (manager backend)
Nhận query text HOẶC PDF (PDF → utils.extract_text Phiên 1) → embed → 1 SQL CTE: ANN top-60 + ts_rank_cd top-60 → RRF(60) → max-pool → dedupe parent. ef_search=100 (as-built).
E4 · Eval harness — cổng quyết định
ranx · nDCG@10 / Recall@50 / MRR@10 · ~300-500 query synthetic (Ollama) + 50-100 gold hand-label · A/B model & chunk & hybrid.
E5 · Reranker (có điều kiện)
chỉ sau khi E4 cho thấy trần hybrid · A/B AITeamVN/Vietnamese_Reranker vs ViRanker · CHỈ chạy offline trên Mac (server 16GB no-GPU không rerank live) · ngưỡng "không có án tương tự rõ".

Rủi ro phải nhớ

Eval — GIẢI bằng synthetic (sinh query từ bản án, gốc = đáp án): đủ để A/B chọn model/chunk. Caveat: synthetic lạc quan → thêm gold set người-duyệt nhỏ để chốt release (không chặn build).
Rác OCR kéo trần — embed/index chỉ từ text sạch; doc reocr/garble làm hỏng cả dense lẫn lexical.
Bẫy "giống giả" trong luật — cùng trích "Điều X" làm 2 vụ không liên quan trông giống nhau với cả vector lẫn LLM-judge. Chỉ eval người-duyệt mới chặn được.
Eval synthetic lạc quan ảo — query do LLM sinh thường dễ/trùng từ vựng → thổi điểm. Chỉ dùng để so config, không dùng làm điểm tuyệt đối.

👉 2 quyết định cần bạn chốt trước E0

① Phần cứng prod → ĐÃ CHỐT: server 16GB no-GPU + app tải về (client embed). Dùng halfvec; reranker để OFFLINE trên Mac (server không GPU → không rerank live).

② 53% doc Quyết định thủ tục (không có tình tiết vụ án): index + gắn nhãn để lọc (vẫn tìm được khi cần), hay loại hẳn khỏi tìm-theo-tình-tiết?
Đề xuất: index hết + tag, để thẩm phán bật/tắt — linh hoạt hơn loại bỏ.

③ Query bằng PDF dài embed thế nào: trích "nội dung vụ án" của query rồi 1 vector, hay chunk query + multi-vector fuse (doc-to-doc)?
Đề xuất: thử (a) trích-facts trước cho đơn giản, để (b) chunk-fuse khi cần độ chính xác cao hơn — cùng dùng splitter Phiên 1.
